# 充电时间与首页下拉刷新兼容性审查

2026-11-24，审查范围为充电时间展示和天幕下拉刷新。未发现阻塞本次发布的代码问题；以下结论区分代码、固定样本与实车验证。

## 车型与数据

| 场景 | 行为及证据 |
| --- | --- |
| P2 正在充电 | ICUP 电池字段 5 映射到 `minutesToFull`；实车返回 360 分钟、约 6.6–6.7 kW，首页与充电页显示 6 小时。`minutesToTarget` 未返回，不再用于该展示。 |
| P2 未充电 | 实车返回 `chargeState=2`、`minutesToFull=0`；首页显示空闲，不显示充电摘要，切换账号后未混入上一辆车的时间。 |
| P4 | xchanger 的 `timeToFullyCharged` 映射到 `minutesToFull`，充电状态由核心层归一化。已复核正常、暂停、准备、失败和字段缺失分支；本轮未连接 P4 实车充电。 |
| 时间缺失或异常 | 失败读数、缺失、非数字、负数、非有限数或超过七天的值不展示为有效剩余时间；充电中明确显示未返回。零值有效。 |
| P4 降级读取 | 单独的充电端点可能仅返回电量与连接状态；缺少充电状态和时间时不推算首页倒计时。 |

首页摘要仅在电池读取成功且归一化 `chargeState=1` 时出现。继续显示车辆上报时间，剩余时间是厂商估值，并非持续递减的本地时钟。账号、车辆、能力、命令记录、历史和备份格式均沿用既有逻辑。

## 平台与交互

| 平台 | 本次覆盖与边界 |
| --- | --- |
| macOS | 共用前端与 Rust 适配；P2 充电和未充电数据已在本机应用核对。桌面新增鼠标下拉；触控板双指滚动没有绑定刷新。 |
| Windows | 共用桌面前端与车型适配，无本次新增的平台专用 API；实际 Windows 交互待验收。 |
| iOS | 共用前端与车型适配；触摸手势通过非被动 `touchmove` 阻止原生滚动。最低系统的弹性滚动及实际手感待真机验收。 |
| Android | 共用前端与车型适配；下拉功能早期开发 APK 已覆盖安装，当前发布包和物理手势仍需真机验收。 |
| HarmonyOS | 共用界面；P4 适配器现有编译范围不包含 HarmonyOS，不能据此宣称 P4 支持。 |
| Web 演示 | 下拉调用模拟刷新，演示标识保留；原生充电时间接线不改变演示数据。 |
| Watch、Siri、小组件 | 本次没有新增这些入口的充电时间或下拉界面；沿用上一版已实现的行为。 |

下拉与按钮调用同一刷新入口。按钮、链接、表单、可滚动子区域、弹窗、非首页和非顶部不会被抢占；同步请求锁阻止重复读取。切页、切车、卸载会撤销动画等待。固定样本已覆盖成功、部分失败、连接失败、重试、短下拉、取消、多指和等待期间切页。合成触摸事件不等同物理手指验证。
