# Siri 实施任务计划

更新日期：2026-11-18，时区 Asia/Jakarta（UTC+07:00）。对应[接入方案](siri-integration.md)，评估基线为 Norr `2696aa7`。

首期代码和测试包已交付。以下清单保留原有阶段与验收条件，实际验证进度以文末的实施记录为准。

## 阶段与预算

以下是工程估算，P0 后按实际阻断点调整。人日包含实现与对应验证，不包含等待设备、车辆、证书及长周期续签的时间。

| 阶段 | 任务 | 本阶段人日 | 累计人日 | 阶段完成条件 |
| --- | --- | ---: | ---: | --- |
| P0：可行性验证 | SIRI-01～02 | 1～2 | 1～2 | 真机能发现 Intent，后台调用 Rust 查询并返回；记录凭据与签名边界 |
| P1：共用服务与查询 | SIRI-03～05 | 2～3 | 3～5 | 电量、续航和门锁查询通过，默认车辆、多车及登录异常有明确结果 |
| P2：核心控制 | SIRI-06～08 | 2～3 | 5～8 | 锁车与空调启停可测试，记录、确认和语音结果闭环 |
| P3：生命周期与回归 | SIRI-09～12 | 3～4 | 8～12 | 超时、取消、重复请求、账号变化和版本兼容有验证证据 |
| P4：安装与实车验收 | SIRI-13～15 | 2～3 | 10～15 | 最终重签包通过规定设备与车辆场景，形成发布说明 |

5～8 人日对应核心可测试版，10～15 人日对应首期完整交付，二者不相加。先前评估中仅打开页面的 0.5～1 人日、只读最小验证版的 2～3 人日属于较小范围，不等同于本计划的服务整理和完整查询阶段。

关键依赖为 P0 → P1 → P2 → P3 → P4。测试样本和验收记录可随实现准备；本计划不假设通过增加并行开发人员缩短上述工期。

## P0：可行性验证

### SIRI-01：验证主 App 中的 Intent 调用链

- [ ] 在 iOS 主 target 添加最小只读 Intent 和 App Shortcut，确认最终应用包含可发现的元数据。
- [ ] 添加最小异步原生桥接，执行 Rust 单项查询并向 Siri 返回结构化结果，不通过页面 JavaScript。
- [ ] 验证未运行、前台、后台挂起及用户强制结束后再次调用的实际行为，分别记录系统是否允许执行或要求打开 App。
- [ ] 记录主进程、Tauri 插件、数据目录、Rust runtime 和服务初始化的实际顺序。

依赖：可安装到真机的签名构建、已登录测试账号和 Siri 环境。完成证据：系统版本、包版本、操作步骤、脱敏日志和录屏；至少在无前台页面的场景完成一次查询。发生强制结束等系统限制时记录可复现的降级行为，不要求绕过系统限制。

### SIRI-02：核对凭据、存储与分发条件

- [ ] 检查已有 Keychain 条目的可访问性与文件保护状态，不输出凭据值。
- [ ] 验证锁屏、重启后首次解锁前后、令牌有效和过期时的恢复行为。
- [ ] 试验当前签名方式下的动作发现与执行，记录 AltStore 重签后的应用标识和必要权限。
- [ ] 输出 P0 结论：主 App 方案是否成立、未解决条件、是否需要扩展，以及修订后的预算。

依赖：SIRI-01。完成条件：明确支持的执行情形与失败返回；凭据不可访问时不清空账号。若必须增加扩展，先更新方案和存储边界，再进入后续实现。

## P1：共用服务与查询

### SIRI-03：提取车辆服务和初始化入口

- [ ] 从 `lib.rs` 中提取查询、执行与记录服务，让现有 Tauri 命令继续使用它。
- [ ] 建立一次性且可等待的初始化，统一 Intent 与页面使用的目录、历史和会话实例。
- [ ] 把事件、通知和窗口交互保留在宿主适配层，服务不依赖 WebviewWindow。
- [ ] 保持旧历史、设置与备份格式兼容，新增字段有兼容读取规则。

依赖：SIRI-01、SIRI-02。完成条件：原有页面功能通过回归；页面与 Intent 同时启动不创建两套可写状态，不覆盖旧记录。

### SIRI-04：实现异步 Swift/Rust 桥接

- [ ] 定义受限请求与结果类型，包括请求身份、动作、账号上下文、VIN、数据时间和错误类别。
- [ ] 明确跨语言数据所有权、释放、线程切换与回调恰好完成一次的规则。
- [ ] 传递取消与超时状态，区别尚未提交和提交后结果不明。
- [ ] 仅暴露首期动作，参数校验和账号能力检查留在 Rust 服务中。

依赖：SIRI-03。完成条件：模拟成功、失败、取消和重复回调均有测试；主线程不执行阻塞网络等待；日志和响应不包含 token。

### SIRI-05：实现车辆实体与查询动作

- [ ] 实现车辆实体、实体恢复与查询，按当前账号过滤，处理删除、失效、切账号和多车消歧。
- [ ] 实现电量与续航、门锁状态查询，使用单项读取并返回可用值和各项时间。
- [ ] 定义默认车辆优先级与缓存规则，已有显式车辆失效时不得自动替换。
- [ ] 覆盖未登录、续期失败、能力未知、明确不支持、权限不足和部分读数缺失。

依赖：SIRI-04。完成条件：Siri 和快捷指令都能查询；使用固定样本证明旧数据、未知值和读取失败不会被播报成实时成功。

## P2：核心控制

### SIRI-06：统一发令、回执与回读

- [ ] 冷启动先恢复车队和能力，再校验命令；保持主账号与共享账号的现有合法路径。
- [ ] 提交前保存请求身份、账号、VIN、目标和时间，记录失败时不发送。
- [ ] 对接 `prepare`、`execute` 和 `confirmation`，分别保存服务回执与车辆确认。
- [ ] 增加未决请求的去重与冲突处理，网络不确定时先回读，不自动重发。

依赖：SIRI-03、SIRI-04、SIRI-05。完成条件：模拟网络计数证明重复或超时恢复不会再次提交原命令；回读早于命令、状态不匹配或 VIN 不同均不能标记完成。

### SIRI-07：实现锁车和空调启停 Intent

- [ ] 添加三个显式动作及系统认证策略，提交前给出车辆与操作确认。
- [ ] 空调启动沿用 `value = None` 的默认路径，保留缺少手动调温能力的合法启停。
- [ ] 用户取消确认时不发令；提交后取消等待保留待核对记录。
- [ ] 拒绝首期范围外的动作，不改变已有应用内敏感操作验证。

依赖：SIRI-06。完成条件：模拟请求覆盖认证取消、确认取消、能力拒绝、受理、确认完成和结果不明；三类控制可进入受控实车验收。

### SIRI-08：注册中文短语与语音结果

- [ ] 添加 AppShortcutsProvider、中文资源和应用名称配置，使用 `.applicationName`。
- [ ] 在系统中验证 `Norr / 北行` 的识别及每个动作的建议短语，不依赖用户先手工搭建快捷指令。
- [ ] 把服务结果映射成语音与快捷指令可消费的输出，区分受理、回读完成、缓存和未知。
- [ ] 检查车辆名称、单位、数据时间与错误说明；示例读数仅用于明确标注的测试样本。

依赖：SIRI-05、SIRI-07。完成条件：五个首期动作可以被发现，建议短语能触发正确动作，语音不会把受理播报为完成。此时达到累计 5～8 人日的核心可测试里程碑。

## P3：生命周期与回归

### SIRI-09：处理超时、取消与恢复

- [ ] 根据 P0 实测设置整体请求预算和局部回读预算，避免沿用无限等待。
- [ ] 处理系统终止、应用切后台、网络中断和用户取消，保存已提交操作的真实状态。
- [ ] 下次运行时恢复待核对操作；超过现有回读有效时间时保留未知结论，不用过晚状态证明历史执行成功。
- [ ] 不依赖现有前台采集循环保证后台回读，也不承诺返回后持续运行。

依赖：SIRI-06、SIRI-07。完成条件：在提交前、提交中、提交后分别中断执行，重启后记录可解释且无自动重发。

### SIRI-10：验证并发、账号和凭据一致性

- [ ] 覆盖页面查询与 Siri 控制、两个 Siri 请求、多个快捷指令同时执行。
- [ ] 验证令牌续期只有一个协调入口，过期结果不会覆盖新会话。
- [ ] 覆盖执行期间切车、切账号和清除登录，结果只归属于原请求身份。
- [ ] 验证忙碌提示、操作冲突、存储失败与应用恢复后的状态一致性。

依赖：SIRI-09。完成条件：记录无串车、串账号、重复写入或历史丢失；失败场景保留可恢复信息。

### SIRI-11：完成系统版本与认证兼容

- [ ] 保留 iOS 15 主应用兼容目标，只在符合条件的系统注册 Siri 功能。
- [ ] 检查每个使用到的 App Intents API 可用版本，为较新运行模式接口提供适用的兼容路径。
- [ ] 在最低支持 Siri 版本与当前版本验证动作发现、认证和执行；缺少测试系统时记录缺口并收窄发布声明。
- [ ] 核对锁屏、设备重启及文件保护，认证失败不得被映射为退出登录。

依赖：SIRI-02、SIRI-08、SIRI-09。完成条件：编译与实际运行证据分别记录，不以最新系统上的结果替代低版本验收。

### SIRI-12：补充自动回归

- [ ] Rust 测试覆盖能力、授权、回读时间、重复提交、持久化失败和账号隔离。
- [ ] Swift 测试覆盖实体解析、参数与结果映射、异步桥接和取消语义。
- [ ] 打包检查覆盖 Intent 元数据、Swift 注册代码和本地化资源实际进入产物。
- [ ] 对提取服务涉及的平台执行现有检查，保持 Tauri 协议和页面行为兼容。

依赖：SIRI-09、SIRI-10、SIRI-11。完成条件：固定样本与模拟请求测试通过，不访问真实凭据、不发送短信或车控；记录实际命令和结果。

## P4：安装与实车验收

### SIRI-13：验证最终签名安装包

- [ ] 构建 iOS 模拟器包与 unsigned IPA，检查 Intent 元数据、嵌套包和签名。
- [ ] 用实际支持的签名方式安装，确认系统能发现动作并完成查询与授权流程。
- [ ] 验证覆盖升级后的会话、默认车辆和已保存快捷指令；重新签名后再次检查。
- [ ] 记录版本、构建号、包 SHA-256、设备系统和签名方式，长期续签另列观察项。

依赖：SIRI-12。完成条件：验收针对最终包，不能仅以 Xcode 开发构建结果替代重签包。

### SIRI-14：完成真机和实车验收

- [ ] 按下方矩阵执行查询、认证和控制，分别记录主账号与共享账号的适用结果。
- [ ] 每次实车控制使用当前明确授权的车辆与动作；取消类用例确认没有请求发送。
- [ ] 保存服务回执、独立回读及各自时间，脱敏后归档；界面或语音成功不单独作为车辆完成证据。
- [ ] 对无法复现或未覆盖场景标记待验证，说明对发布范围的影响。

依赖：SIRI-13。完成条件：首期公开声明的场景均有证据；已知限制写入安装和使用说明。此计划本身不授权发送真实车辆命令。

### SIRI-15：整理发布说明与使用文档

- [ ] 记录支持系统、车型、动作、认证行为、推荐短语和快捷指令使用方式。
- [ ] 说明授权失效、缓存读数、结果待核对、锁屏限制和重签后的排查步骤。
- [ ] 更新 README、PROGRESS、原生说明及对应版本说明，保留未完成验证项。
- [ ] 将最终证据关联任务；故障时可停止注册受影响动作，同时保留已发送命令记录与既有页面功能。

依赖：SIRI-14。完成条件：版本范围与实际验收一致，文档中的任务状态按证据更新。发布到外部渠道按届时任务授权执行。

## 验证命令与证据格式

下列命令覆盖工作区、Swift 桥接和 iOS 产物。

```sh
npm run check:native
npm run typecheck
npm run build
npm run build:ios
npm run build:ios:unsigned
node --test apps/native/scripts/ios-signing.test.mjs
sh apps/native/scripts/check-siri.sh
```

iOS 模拟器和设备构建共享归档位置，应顺序执行。Swift 桥接测试通过固定样本检查返回值、缺失读数、错误和取消。服务提取影响其他平台时，补充相应目标的编译检查；若修改 Watch，再执行 `node apps/native/scripts/check-watch.mjs` 和 Watch 构建。

每份验收记录至少包含任务与用例编号、日期、源码提交、构建号、设备与系统、签名方式、前置状态、实际结果、证据位置和未覆盖项。车控记录额外保存脱敏请求身份、发送时间、服务状态和车辆回读时间，账号、VIN、token 和签名资料不得写入公开记录。
