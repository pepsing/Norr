**2026-11-23 更新：** macOS `polestar4-test` 已接入 xchanger 空调启停和充电上限写入，复用现有确认框、指令记录与车辆回读。发送前重新核对同账号车库 VIN 和对应能力，结果不明不自动重发。固定样本、模拟 HTTP 服务及浏览器 IPC 验证已通过；当前实现的实车执行、其他平台写入仍待验证。详见 [P4 控制接入](../polestar4-controls.md)。下文保留首版范围与后续能力规划。

## 现有页面如何匹配

| 现有位置 | P4 数据或能力 | 设计与验收条件 |
| --- | --- | --- |
| 车辆选择、车辆图 | 中国区车库含 P2、P4，Geely 车库返回 P4。已有 P4 外观素材 | 按当前账号的 VIN 合并为同一辆车，继续使用现有选择器和外观配置。车型名用于展示，平台与车辆归属用于服务路由 |
| 车辆首页、充电页能源卡 | 电量 chargeLevel、当前续航 distanceToEmptyOnBatteryOnly；满电预估另有字段 | 同一份读数供两页使用。保留真实 0、缺值和车辆上报时间。首页使用当前续航 |
| 车门与门锁、座舱温度、车身详情 | 中控锁、分门开闭、尾门、前舱盖、车窗、内外温度、预空调状态 | 沿用已有位置。锁定与关门独立解码；P4 车窗 0 代表微开。温度、空调运行状态分别判断，缺项仅影响对应行 |
| 健康与保养、行程读数 | 总里程、距保养天数与里程、轮胎警告、行程表和均速字段 | 总里程按 km。保养单位和警告枚举逐项核对。P4 逐轮实测压力按 kPa 取整显示，参考压力和告警枚举仍缺依据。行程表先核清统计周期再填入手动、自动或充电后栏 |
| 空气质量 | 车内 PM2.5、空气等级，另有部分外部空气等级字段 | 单位核实后填对应指标。污染等级、浓度、AQI 和预清洁运行状态分别取值 |
| 车辆位置 | 有位置、可信标志、坐标系相关字段 | 可信值、坐标系与地图转换核对后，复用现有地图和外部地图链接。无效位置呈现未知 |
| 充电状态与读数 | 插枪、充电状态、剩余时间，另有交直流功率、电流、电压等字段 | 按官方四字段规则区分预约、暂停、充电中等状态。功率、电流和时间核对单位及 AC/DC 来源后复用。充满时间与充至目标时间分别处理 |
| 记录页 | 本机已有采集记录、电量/里程趋势和推导的行程、充电记录 | 沿用本机来源，按账号和 VIN 分组。相同上报时间的缓存可保留采集记录，但不重复生成趋势点、行程或充电事件。厂商行程日志另见决策 4 |
| 设置 | 账号、外观、备份、采集频率、通知与系统 | 沿用现有页面。P4 授权生命周期由后端管理，沿用 P4 测试包独立凭据。仅对已接入的记录类型启用对应通知 |
| 软件、安装日程、充电地点 | P4 尚缺已验证的版本、日程和地点列表来源 | 三项分别记为待适配。空列表须来自成功查询；缺少接口时不能显示“无预约”或“已是最新”。呈现方式见决策 1 |

**更新状态。** 已观察到请求成功时附带旧车况、车辆上报时间及“刷新已提交”。复用已有时间行，展示“车辆上报于 … · 等待更新”。收到同一车辆更新的上报时间后才推进观测时间。单个端点超时仍可显示其他成功读数。来自独立充电接口的值若无车辆时间，只标记读取时间。

以下匹配表示用户意图相同。P4 实测覆盖读取、认证与能力声明，动作的执行和回读仍待逐项验证。

| P2 现有动作 | P4 证据 | P4 建议 |
| --- | --- | --- |
| 锁车、解锁 | 官方 App 4.25.0 的 P4 车身适配器分别实现闭锁和解锁 | 复用车锁入口，两个方向分别对照中控锁回读 |
| 开启、关闭空调 | 驻车空调有独立启停方法，车况能读预空调状态 | 复用空调入口，温度和加热分别按下列三项验证 |

| 主驾、副驾座椅加热 | 官方 P4 座椅页分别展示关闭和 1 至 3 档。座椅状态 detail 为 0 时显示关闭，否则读对应座位的档位 | 空调详情及车况日志分别记录主驾、副驾。后排字段的存在尚不能证明可从 App 调节后排 |
| 主驾、副驾座椅通风 | 车主 iPhone 录屏的座椅页显示两个通风按钮。Android 手机版 AirSeatFragment 将各座位 VentSts 与 VentDetail 配对，独立于加热档位 | 实车快照按座位解析并记录通风档位。缺值和未知编码保留未知。演示使用原有空调弹窗 |
| 方向盘加热 | 官方 P4 座椅页按开关展示方向盘加热。只读样本含 steerWhlHeatingSts | 详情和日志记录已知开关值，缺失或未知编码保留未知。验收时核对指令发出后的上报时间 |
| 单独闪灯、鸣笛并闪灯 | 寻车支持两种独立动作，另有单独鸣笛 | 首页和控制页的寻车面板均按闪灯、鸣笛并闪灯、单独鸣笛排列 |
| 解锁尾门、电动开关尾门、开关车窗 | 尾门解锁及车窗两个方向均有实现。电动开关尾门调用默认的不支持分支 | 车窗按四个窗位回读；尾门解锁看 trunkLockStatus，升降看 trunkOpenStatus。当前 Norr 的 tailgate 读数只表示开启状态 |
| 开始、停止空气预清洁 | 驻车空气预清洁有独立启停方法 | 复用净化入口。官方 P4 转换器 v7/clido.java 用 climateStatus.airBlowerActive 表示净化开关，interiorPM25 单独表示浓度。Norr 将有效开关值解码为净化运行状态。只有浓度时，净化运行状态保持未知 |
| 打开、关闭充电口盖 | P4 车身适配器实现两个方向，业务层各有对应动作 | Norr 已读取 chargeLidDcAcStatus。界面入口待决策，需对照实车盖板状态 |
| 充电上限、交流电流上限 | 目标电量有独立读写方法，设置交流电流上限抛出未实现错误 | 充电设置分项标注，目标值的取值范围待确认 |
| 临时立即充电、恢复充电日程 | 车辆声明远程充电，P2 两个按钮涉及覆盖和恢复日程 | 暂无足够证据认定行为相同 |
| 保存充电窗口 | P4 有单次与周期预约能力，P2 的充电窗口方法在 P4 分支返回不支持 | P4 预约编辑器见决策 3 |
| 保存、删除空调日程 | P4 的新增、更新和删除实现均带废弃标记。新增分支创建异步请求后未见订阅便返回；不能仅凭方法存在判定已写入 | 保存入口需分别验证新增与更新，实车回读需核对时区和预约 ID |
| 预约安装、立即安装、取消安装计划 | 本轮无 P4 OTA 写入证据 | P4 隐藏软件更新入口和三项操作 |

依据为中国区官方 App 4.25.0 的 P4 适配器。解包源码目录下，车身实现见 `y7/clivoid.java` 和默认行为 `y9/cliif.java`，寻车见 `z7/clitry.java` 与 `HonkFlashType.java`，空调见 `v7/clisuper.java`，充电见 `u7/clibreak.java`。这些结果说明该版本客户端如何处理各项操作。本车的写入权限、服务回执和执行结果仍待验证。空调启停与充电上限已按文首更新接入，其他写入保持待适配。

## P4 新能力和产品决策

本车实测的 56 项配置全部标为启用，其中包括读数、提醒、服务基础设施和操作。下列建议均以这辆车为样本。“暂缓”表示交给产品决定优先级。车型能力缺失与明确不支持应分别保存。

| 编号 | 待你决定 | 建议及交互代价 | 可选方案 |
| --- | --- | --- | --- |
| 1 | P4 未匹配功能和首页四个快捷入口 | **保留车锁、空调、尾门、寻车的位置**。有车况的入口可打开已有详情，寻车直接打开动作列表，各项说明接口匹配情况及 Norr 接入状态。详情内完全无来源的栏目折叠。切车时位置稳定 | 按本车可用功能动态缩减快捷区；或把所有未接入项目列出并禁用 |
| 2 | 轮胎无压力数值、驻车舒适/露营等模式有字段时如何展示 | **健康页仅列有证据的逐轮状态**，取得有效 kPa 后显示压力列。模式枚举核实后在已有车辆详情增加只读行。首屏保留电量和续航 | 维持统一胎压表并以“未知”填空；模式另设独立卡片 |
| 3 | P4 临时充电、单次/周期预约是否沿用 P2 充电窗口 | **保持充电页入口，按已验证的语义呈现编辑器**。先读取计划；若 P4 区分单次与周期，在编辑器内选择类型并核对次日、跨午夜、时区与计划 ID。若仅有启停，单设“开始/停止充电”语义 | 首版只展示计划；或延后全部预约交互，等能完整回读再接入 |
| 4 | 行程日志开关、单次能耗/均速、百公里电耗、远程诊断 | **统计量优先放入已有行程详情，故障摘要放健康页**。先验证单位、统计周期和数据来源。云端行程若纳入记录页，需区分来源并核对重复行程。日志开关涉及是否记录行程，须独立设置 | 仅保留本机历史；或新增带来源筛选的云端行程视图 |
| 5 | 低电量、电池温度、充电、保养、胎压、碰撞、防盗/拖车、活物/遗留物等提醒 | **暂缓新增推送入口**。字段快照可支撑状态展示；有可靠事件 ID、时间、权限和去重规则后再考虑设置页分类订阅。驻车舒适低电量等属于提醒 | 先试点充电与保养两类；或仅在详情展示可核实的状态 |
| 6 | CCC 数字钥匙、远程允许启动、私密锁、防盗追踪 | **单独立项**。数字钥匙涉及设备和钥匙生命周期，私密锁与普通车锁的对象不同，启动授权和追踪需要独立的角色与交互评审 | 指定某一能力做下一轮可行性调查；或从 Norr 的产品范围排除 |

车联网服务、心跳长连接等基础配置没有直接的用户动作，建议仅用于内部服务选择。提醒配置如“下雨关窗提醒”不能推导为手动车窗控制。后台标为启用也不能单独用来决定通知来源、钥匙权限或控制按钮。

## 平台隔离与数据契约

1. **在原生服务边界分流。** 当前宿主直接持有 ChinaClient，现有 vehicle() 对 ICUP / AccountLinking 做了校验。首版仅在 P4 测试构建加入分流：已识别 P2 调原实现，P4 候选按车库平台并用同一账号的 Geely 车辆列表核对 VIN，命中才建 P4 客户端。若实际平台值缺失或不明，保留待适配状态；不按车名绕过归属检查。普通构建仍使用原入口。中国区车库 connect() 当前还会连接 C3 通道，P4 测试构建应允许元数据发现与 P2 通道连接分别失败，避免 Geely 或 C3 的局部故障拖垮另一台车。
2. **P4 适配器负责转换。** 将已验证的只读协议纳入原生核心；Python 工具继续作为验证参照。一次综合车况响应拆成多个现有 Reading，同轮按 VIN 合并请求。对当前账号、VIN、采样时间和字段来源分别归档。SDK 授权配置的分发需在正式打包前确定，安装包运行时不依赖本机解包目录。
3. **兼容现有快照。** 沿用 Vehicle、Snapshot、Reading、Receipt。P4 的缓存/等待更新、能力来源和动作状态优先作为可选字段，新字段缺省时走现有 P2 逻辑。Norr 的统一枚举由 P4 转换层生成。厂商未知值、空值、无权限和网络失败保留区别。时间来源传到首页、历史与回执，缓存不能确认控制已执行。
4. **逐项能力判定。** 为 P4 单独保存厂商声明、已接入的读写操作和本次授权结果。前端 unavailableReason 及原生提交入口使用同一份 P4 动作判定。车库列表、读取、命令准备和提交均按账号与 VIN 校验。不能仅把 HUANFU 加进现有 P2 白名单，否则按钮可能进入 C3 调用。演示能力表不参与原生判定。
5. **凭据与并发。** 用安全存储中独立的 Geely 授权及账号作用域，续期成功后原子保存。若刷新响应仅给出新访问令牌则保留已有刷新令牌。原生客户端和测试工具共享续期互斥，切车或换号后丢弃旧响应、待执行动作和临时状态。每个错误对应当前账号与车型，P4 授权失败只影响 P4。
6. **发布和回滚。** 账号隔离的测试包与 P4 适配开关分别管理。先在 macOS 测试构建验收；以后推广到普通包不应因此切换原应用的存储命名空间。关闭 P4 适配后仍可读取既有 P2 历史。Widget、Watch、Siri 及后台通知有独立数据入口，P4 读数与授权模型完成各端验收后再纳入。

## 实施顺序与验收

| 阶段 | 交付和通过条件 |
| --- | --- |
| P2 基线 | 保留一组脱敏 P2 车库、14 类读取、能力真假/缺失、既有命令准备与回执、历史备份样本。普通构建继续通过原检查，并验证读取 P2 的请求序列和输出，Geely 请求数为零 |
| 测试包只读 | 混合车库内来回切车。用合成或脱敏样本覆盖并发返回、换号、单服务离线、字段缺失、缓存等待、部分读取成功。P4 只读入口复用现有页面；写入入口在原生层拒绝。恢复测试包验证免验证码、相同上报时间不重复生成事件 |
| 产品决策与扩展 | 按上表逐项选择后再排期。控制候选先验协议、账号权限、参数范围、失败与超时语义，再用模拟回执验证确认流程。真实动作按另行安排逐项验收，涉及车辆状态的动作要求比指令更新且一致的回读 |
| 发布验收 | 普通构建和测试构建各跑 npm run check:native 及前端相关检查。P2、P4 分别走实际 macOS 入口，核对五页、后台、备份恢复和回滚；确认 P2 原账号、钥匙串命名空间、历史与快速操作均与基线一致 |

设计审查按项目 DURING 约定执行。Hard Gate PASS，页面数据、声明与实测边界已标出；Purpose Gate PASS，所有新增入口均有用户决策项；Liveliness PASS，沿用现有车辆图、能源主卡和五页结构；Craftsmanship PASS，覆盖新旧快照、混合车库、故障隔离和回滚。以上为方案审查，运行验收列在实施阶段。
