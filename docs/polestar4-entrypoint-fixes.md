# P4 现有入口适配修复

2026-11-24，保留 P2 的现有功能范围。前轮交付本地 macOS `0.2.1-dev.1023`；本次适配与下述剩余问题修复已发布为 GitHub `0.2.1-alpha.8` 和 TestFlight `0.2.1 (1024)`，TestFlight 的 Norr 公测组已显示“正在测试”。此前桌面测试包未替换。

## 变更

- 手机与 macOS 小组件继续显示主应用快照，点击刷新或控制仍进入主应用。P4 缺少车辆上报时间时不再使用本机读取时间，等待更新的缓存明确标识。P2 的时间兼容规则不变。
- Siri 与快捷指令沿用六组入口。P4 开后备箱实际映射为 `unlockTrunk`，确认和回执均明确“解锁”；关闭尾门在发令前拒绝，保留 P2 电动开关语义。
- Siri 的待核对判定复用主应用的 P4 规则。已确认空调运行但温度待核对时可关闭；已确认车窗留缝后可关闭。未知、过时、账号不一致的记录不冒充成功，不自动重发。
- iOS 服务实例按应用基础目录复用，首次创建时解析账号历史路径。登录后仍使用同一实例并切换账号历史，避免 Siri 冷启动或登录后访问固定旧路径而报“车辆服务数据目录不一致”。
- Watch 为 P4 接入既有车况、锁车/解锁、22°C 空调启停及充电读取。iPhone 同步访问授权和签名上下文，手表独立请求 xchanger；refresh token 仍只留手机，续期后重新同步。不添加手机转发控制或新的用户操作。
- Watch 的 P4 读写核对自有/共享车辆和能力，未返回字段保持未知；新上报、目标值和车辆身份同时符合才确认命令。车型对应车图沿用仓库 Snow 透明素材，表盘缓存同步标记等待更新。
- 补齐共用 `uses_xchanger` 判断的 Android 平台分支，使其使用同样的 P4 待核对和回执记录规则。

此前排查将 Siri 的十分钟拦截描述为主界面已放行，需要更正：主界面使用专门的 P4 拦截规则。本轮统一判定，不移除对结果不明指令的保护。

## 验证范围

固定样本覆盖 Siri 尾门语义、P2 兼容、P4 回读策略、账号切换服务复用、小组件身份/车图/零值/上报时间、Watch 签名与参数、授权有效期、能力缺失、拒绝与未知回执。测试不读取实际凭据或发送车辆命令。

已通过 105 项工作区 Rust 测试、30 项前端测试、40 项构建/发布脚本测试、Swift Siri/Watch 样本、工作区与 iOS ARM64 严格 Clippy、iOS App Intents 类型检查、watchOS ARM64_32 类型检查和 Watch 模拟器编译。macOS ARM64 包包含 Widget 扩展，应用和扩展均为 `0.2.1-dev.1023 (1023)`，使用本地 `.env.secrets` 配置构建，密钥值不输出或提交。嵌套签名、ZIP 完整性和密钥注入检查通过；产物与校验记录保存在 `target/p4-integration-20261124/verification.json`。

P4 真机 Siri 语音、冷启动、iPhone/Watch 授权传递、手表网络与续期、实车控制和表盘显示尚未验收。macOS 包仅能测试桌面车辆页面、小组件和共用 P4 核心，不能验证 iOS/Watch 系统调用。

## 剩余问题修复

- Watch 将门锁与空调的待核对记录分开。同账号、同车辆、同类操作在发出后的十分钟内阻断重发；其他操作可用。刷新可消除足够新且匹配的记录；十分钟后仍保留未确认结果，核对只更新当前车况，不把当前状态追认为旧操作成功，也不自动发送。切换账号、车辆及重启保留隔离规则。
- P4 读取先检查当前自有/共享车库。能力接口失败或车辆类型缺失时，继续读取车况与充电目标，能力保持未知；车辆不在车库时立即停止。控制前仍重新核对车库和能力。
- Siri 查询与控制回读保存到当前账号历史，保留其他接口的读数，拒绝用较旧的读取或车辆上报时间覆盖新数据，并通过现有 `vehicle-updated` 事件更新页面。冷启动无需页面运行也可保存历史、更新现有小组件；组件必须匹配原生写入的账号标记与 VIN，旧缓存先由主应用刷新一次。
- iOS/macOS 在退出账号、无车或选中车辆无快照时删除旧组件记录并请求系统刷新。iOS 正常同步与 Siri 回读共用串行写入，较旧同步不会覆盖新回读；不重建已清空或其他账号/车辆的组件，保留车图与外观配置。

本轮通过 108 项工作区 Rust 测试、30 项前端测试、42 项脚本测试及 Swift Siri/Watch 固定样本。Watch 使用 `URLProtocol` 模拟能力接口 503、缺少车辆类型与车辆不在车库，未连接真实服务。组件测试覆盖重复清空、保留车图、换号/换车、旧时间拒绝、旧记录兼容；Siri 测试覆盖局部合并、回执更新、落盘恢复和账号历史隔离。

工作区与 iOS ARM64 严格 Clippy、iOS ARM64 库构建、Watch 模拟器构建通过。随后的签名归档发现 Release 优化未导出 `norr_widget_readback`，已将桥接函数声明为 public，完整归档及 GitHub 两类 iOS 构建通过。修复开发未读取真实会话或发送实车请求；发布时按授权读取本地构建密钥并核对注入。检查日志分别位于 `target/p4-remaining-fixes-20261124/` 与 `target/p4-entrypoint-release-20261124/`。此前桌面 `0.2.1-dev.1023` 不包含本节新增改动；Apple 系统调度、真机语音、配对传输与实车行为仍需验收。

## macOS 测试

1. 关闭旧 Norr 后打开本次 `Norr.app`，恢复中国区连接并选择 P4。
2. 对比车辆页与小组件的电量、续航、门锁、车图和上报时间。返回旧数据时应显示等待更新，不能显示成本次刚上报。
3. 点击小组件门锁、空调和刷新入口，核对进入同一车辆、能力提示与确认页。取消确认不应产生车辆命令。
4. 切回 P2，核对原有读数、车图和快捷入口；切换账号后核对历史记录隔离。

Hard Gate PASS：未知数据与实测边界明确，密钥不展示；Purpose Gate PASS：现有入口适配和账号一致性；Liveliness 不适用：沿用既有布局、主题与车辆素材；Craftsmanship PASS：固定样本、跨平台编译与产物检查，真机/实车范围单列待验收。
