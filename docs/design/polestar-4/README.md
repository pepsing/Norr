# Norr 的 Polestar 4 交互稿

2026-11-23 发布接入：P4 生产接口已由 `polestar4` 特性纳入标准构建，包含能力判断、签名请求、服务回执与独立回读。下面保留界面迭代时的验证记录；当时关于待接入写入适配器的描述已由本次实现取代，逐项实车结果仍以 [控制说明](../../polestar4-controls.md) 为准。


浏览器打开 Norr 的本地开发地址，加上 `?demo=p4` 即可进入。iOS 实测界面的「查看功能演示」使用同一个演示车库。操作保存在浏览器或演示 WebView 中。[车辆与座舱](cockpit.jpg) · [车况与能源](vehicle.jpg)

| 入口 | 可以体验 | 设计依据 |
| --- | --- | --- |
| 车辆首页 | 续航、电量、车内外温度，四个固定入口分别为车锁、空调、尾门和寻车。车辆位置使用演示地点 | 录屏开头的车辆首页与寻车地图，沿用 Norr 已定的快捷顺序 |

| 座舱净化 | 查看 PM2.5、启动与停止净化。浓度及运行状态分别显示 | 录屏约 18 至 21 秒 |

## 座舱以外的页面复核

按 Norr 的极星视觉规范和车机参考照片逐页检查。首页继续以续航和车身为焦点，车况页以轮位和读数为焦点。车机照片里的饱和橙用于标出座椅；日期和电量预设用橙色文字与下划线，黑白按钮承担主要操作。[调整前后对照](interface-review.jpg)

| 页面 | 复核结果 |
| --- | --- |
| 车辆、车库、行车日志 | 门锁图标随锁止状态变化。深色行车日志和车库使用透明底侧视图。外观选择器保留统一的摄影棚背景，便于对比车漆与视角。 |
| 车身控制、寻车、净化 | 门锁弹层列出车辆和当前状态，按钮直接标明「解锁车辆」或「锁定车辆」。控制列表与弹层统一使用「尾门」「充电口盖」，「选择寻车方式」进入三个选项。 |
| 车况、位置、健康 | 四轮读数围绕车身排列，胎压与胎温各自带单位。位置和健康沿用单色列表，主要读数及地图入口清晰。 |
| 充电、出发计划、快捷组合 | 手机端使用与座舱一致的底部弹层。「添加」和「编辑」随操作切换，选中日期与充电上限使用同一标记。320 像素宽度下，星期按钮分两行，每个触区至少 44 × 44 CSS 像素。 |
| 指令记录、离线 | 等待核对时不显示成功对勾。闪灯、鸣笛的记录展示服务回执，并说明实车效果需在车旁观察。可回读的状态型指令继续提供「核对状态」。离线时，车锁和充电上限弹层都说明控件停用原因。 |
| 朋友实测页 | 「开始记录」「完成记录」「导出日志」依次成为主按钮。完成后，导出位于车况读数上方；选择旧记录和再次开始记录的入口仍可用。 |

在 320 × 740 深色、390 × 844 浅色、1100 × 900 深色浏览器窗口分别检查了 35 个演示页面和状态，未发现横向溢出或页面运行异常。另用本地模拟原生接口走通两种手机宽度的记录和导出流程。系统分享面板仍需在 iPhone 上验收。

## 交互验收

### 原生接入与 macOS mock 版

原生首页与演示版共用车辆概览组件和前排选座图。原生界面按当前车辆快照显示续航、电量、门锁、内外温度、空气质量、四轮胎压与胎温、座椅档位、行车日志、充电上限和已读取的充电预约。座舱首页在缺少目标温度回读时显示驻车空调状态。车辆未上报的档位或读数保留为未知。旧快照和普通版返回的 HUANFU 车辆也能进入 P4 界面。

实测记录保留车辆上报的充电上限、上报时间与车外温度。旧日志中的 C3 参考值仍单独标记。空调启停和充电上限的命令回执通过当前账号、当前车辆的真实读取客户端独立核对；缺少有效读数或只返回 C3 参考值时继续等待核对。向车辆提交指令的生产适配器仍待接入 Norr 的授权 SDK 或写入接口。

在仓库根目录运行 `npm run build:mac:p4-demo` 可生成 `Norr P4 Demo.app`。它使用独立的应用标识和本地模拟数据，操作可在重启后继续查看。真实接口逻辑在原生构建中，mock 包只启动演示窗口。

控制页的两组操作共用图标、文字和按钮三列。macOS WebKit 在浅色和深色下分别验证了 320、390、420、645、761、920 和 1100 像素窗口。逐行测量七个按钮，宽度均为 112 像素，高度至少 44 像素，右边缘距所在行末端 12 像素。

iOS 实测记录中的车锁、座舱和充电上限沿用主界面的控件。以下结果来自打包后的 Web 资源、模拟 IPC 与原生固定样本。

| 实测控制页检查项 | 结果 | 验证依据 |

| Purpose Gate | PASS | 门锁和空调显示所选车辆的快照，充电上限只列出授权返回的档位。 |
