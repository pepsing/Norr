# Norr P4 iOS Build 6 测试操作手册

适用版本：Norr P4 `0.1.0 (6)`，中国区 Polestar 4 控制与日志测试包。本文从打开应用开始，不包含安装步骤。

本版已接入 21 种控制动作，通过 xchanger 签名并发送真实请求。实际可用项目由账号权限、车辆能力和返回的车况决定。下面列出的是待实车验证的操作与预期结果；现有编译、自动测试及模拟操作通过，不代表这辆车已经验证通过。

## 1. 开始前

1. 确认进入的是 Norr P4 的真实账号和车辆页面，页面底部显示“中国区车辆服务已连接”。核对车型与车架号末四位，避开演示数据。
2. 记录 iPhone 型号、iOS 版本、车辆年款、车机版本，以及主账号或共享账号。共享账号按实际开放的能力测试。
3. 车辆停稳后操作。车钥匙随身携带，门窗、尾门和充电口盖附近留出空间；鸣笛测试选不会打扰他人的位置。
4. 记下原来的空调、座椅、方向盘、充电上限、门锁及门窗状态，测试结束后恢复。充电上限尤其要记住原值。
5. 一次只测一辆车、一个功能。测试期间避免另一人同时从官方 App 或车机下发指令，否则难以判断是哪次操作生效。

首次建议先完成“开始记录 → 读取车况 → 方向盘加热开启和关闭 → 完成记录 → 导出日志”。这条流程跑通后，再按第 4 节做完整测试；若方向盘能力未开放，可换用已开放且便于现场核对的项目。

## 2. 开启日志，并确认初始车况

1. 打开 **设置 → 隐私与数据 → P4 诊断日志**。
2. 点 **开始记录**。页面应显示“记录中。完成时会再读取一次车况。”，并出现 **完成记录、读取车况、刷新车辆**。
3. 等待开始时的自动读取结束，核对所选车辆和返回的数据。失败时先记下提示，再点一次 **读取车况**；能力或车辆列表需要更新时用 **刷新车辆**。
4. 返回车辆页或控制页继续测试。切换页面不会结束本轮记录，测试期间尽量让 Norr 保持前台。

每轮建议只记录一组：座舱、车身、充电与净化、寻车。每组完成后单独导出，方便定位问题。首次测试也可以全部记在一轮中，但要保留各项操作时间。

**先开始记录，再发指令。** 开始和完成时各读取一次车况，期间保存实际采集到的指令与回读；不能用事后开启的记录补齐之前的操作。iOS 后台持续采集尚未验证。

## 3. 每个项目都按这个顺序操作

1. 查看并记录操作前的状态及车辆上报时间。旧数据或“未返回”不能当作当前实车状态。
2. 打开对应入口，选择动作和参数。确认框中核对车辆末四位、动作、温度或档位，再点 **确认执行**。
3. 若出现系统身份验证，按提示完成；取消验证后停止该次操作。只想检查入口时，可在发送前点 **取消**。
4. 打开 **控制 → 指令记录**，记下服务回执和下方的独立回读。**“服务已受理”只表示服务收到了请求，不能据此认定车辆已执行。**
5. 在现场观察，或从车机、官方 App 读取状态。不要为核对结果再从官方 App 发送同一指令。
6. 等待晚于操作时间的车辆上报。没有新数据时，返回 **P4 诊断日志 → 读取车况** 补读一次，再检查记录；仍不明确就保留现场结果并停止该项，不连续重发。
7. 记录本项结论，再进行下一步。下表中的每次档位变化、开启和关闭，都需要分别确认和核对。

页面中的请求时间、采集时间与车辆上报时间含义不同：刚刷新出来的数据，也可能仍是车辆先前上报的旧状态。

## 4. 完整控制测试

### 座舱：7 种动作

统一入口：**控制 → 即时控制 → 空调 → 调节空调**，打开“座舱设置”。车辆首页的 **空调** 也能进入。没有操作权限时，入口可能显示 **查看空调状态**。

先完成空调测试，再进入 **座椅** 标签。座舱图片上的 **主驾 / 副驾** 用于切换座位，操作前核对下面分组的座位名称。

| 编号与动作 | 操作步骤 | 核对内容 |
| --- | --- | --- |
| C01 开启空调 | 在“空调”标签点开启空调；确认框中选择 23 °C，确认执行。支持范围为 16 至 28 °C 整数 | 驻车空调变为运行状态。设定温度另在车机核对；车内温度不必立即达到 23 °C |
| C02 关闭空调 | C01 结果明确后，重新打开座舱设置，点关闭空调并确认 | 驻车空调停止，新回读反映关闭 |
| C03 设置方向盘加热 | 在“座椅”标签的方向盘加热分组依次选开启、关闭，每次单独确认 | 对应开关回读变化，车机或现场结果一致；体感温度不会立即变化 |
| C04 设置主驾座椅加热 | 选主驾，确认主驾通风已关闭；加热依次测试 1 档、2 档、3 档、关闭 | 每档回读与选择一致，副驾状态不因本项操作改变 |
| C05 设置副驾座椅加热 | 选副驾，确认副驾通风已关闭；依次测试 1 档、2 档、3 档、关闭 | 每档回读与选择一致，主驾状态不因本项操作改变 |
| C06 设置主驾座椅通风 | 选主驾，确认主驾加热已关闭；通风依次测试 1 档、2 档、3 档、关闭 | 每档回读与选择一致，车机或现场能核对对应座位的变化 |
| C07 设置副驾座椅通风 | 选副驾，确认副驾加热已关闭；依次测试 1 档、2 档、3 档、关闭 | 每档回读与选择一致，车机或现场能核对对应座位的变化 |

加热与通风切换前，先关闭同一座位的当前模式，等车辆回读确认关闭，再开另一模式。对侧模式未知或车况过旧时，Norr 会阻止切换；这是保护行为，不能通过连续点击绕过。

空调页面的目标温度目前显示“尚无车辆回读”。若记录提示“空调已启动，设定温度待核对”，分别记录运行状态与车机设定温度，不能把这条提示直接记为全部通过或全部失败。

### 车身：8 种动作

除门锁外，以下项目位于 **控制 → 即时控制 → 车辆功能**，点击对应行的 **选择操作**。先确认空间和车辆条件允许，再操作门窗、尾门与口盖。

| 编号与动作 | 操作入口及步骤 | 核对内容 |
| --- | --- | --- |
| C08 锁定车辆 | 门锁卡片 → 车身详情 → 锁定车辆；或车辆首页 → 车锁 | 新回读显示已锁定，现场核对门锁状态 |
| C09 解锁车辆 | 同一门锁入口 → 解锁车辆，按提示完成身份验证 | 新回读显示已解锁，现场核对；随后重新锁车 |
| C10 解锁尾门 | 尾门 → 选择操作 → 解锁尾门 | 现场核对尾门解锁结果。该动作不要求尾门电动升起；尾门仍显示关闭不能单独证明解锁失败 |
| C11 打开车窗 | 车窗 → 选择操作 → 打开车窗 | 现场核对各车窗变化，并查看车窗回读；完成后先执行 C13 |
| C12 车窗通风 | 车窗已关闭后，选择车窗通风 | 现场观察留缝。记录可能显示“车窗已留缝，开度待核对”，不要据此认定精确开度；随后执行 C13 |
| C13 关闭车窗 | 车窗 → 选择操作 → 关闭车窗 | 现场确认车窗关严，新回读反映关闭 |
| C14 打开充电口盖 | 充电口盖 → 选择操作 → 打开充电口盖 | 在车辆允许的条件下操作，现场与回读都反映打开 |
| C15 关闭充电口盖 | 同一入口 → 关闭充电口盖 | 现场与回读都反映关闭；连接充电枪等条件不允许时，记录原因并跳过 |

现场检查门锁时，留意携带钥匙接近或触碰门把手是否引起了新的解锁，避免把后续变化归因于 Norr。尾门解锁后若手动打开尾门，记录这一步，并在结束前关好。

### 充电、空气与寻车：6 种动作

| 编号与动作 | 操作入口及步骤 | 核对内容 |
| --- | --- | --- |
| C16 设置充电上限 | 车辆首页 → 充电上限 → 设置充电上限；选一个与原值不同、适合当前充电安排的值，例如原来 90% 时测试 80%，然后恢复原值 | 新回读及车机/官方 App 的充电上限一致。支持 40% 至 100%，界面按 5% 调节并保留当前值；核对的是上限，不是当前电量 |
| C17 开始空气预清洁 | 控制 → 即时控制 → 座舱空气 → 详情与净化 → 开始空气预清洁 | 净化状态变为运行，结合车机或现场观察。PM2.5 不必立即下降 |
| C18 停止空气预清洁 | 同一入口 → 停止空气预清洁 | 净化停止，新回读反映关闭 |
| C19 闪灯寻车 | 车辆首页 → 寻车 → 闪灯寻车；或控制 → 鸣笛与闪灯 → 选择操作 | 现场确认闪灯，并记下是否伴随非预期鸣笛 |
| C20 单独鸣笛 | 同一寻车入口 → 单独鸣笛 | 现场确认鸣笛，并记下是否伴随非预期闪灯 |
| C21 鸣笛并闪灯 | 同一寻车入口 → 鸣笛并闪灯 | 现场同时确认鸣笛与闪灯 |

三种寻车动作需要分别记录现场结果。服务提示“P4 服务已受理，鸣笛或闪灯结果请现场核对”是预期提示；这类动作没有可靠的持续状态回读，不要求出现“回读一致”。短时间内不要连续点击不同寻车动作。

本轮不要求测试电动尾门打开/关闭、后排座椅、充电电流、立即充电/恢复预约、预约写入、OTA、Watch 或 Siri。这些不在 Build 6 的已启用范围内，入口缺失或禁用不计为本轮控制失败。

## 5. 怎样记录结果

每项同时保留服务回执、车辆回读和现场观察，最后给出结论：

| 结论 | 适用情况 |
| --- | --- |
| 通过 | 车辆出现预期变化，相关新回读一致；寻车以服务受理加现场观察为依据 |
| 部分确认 | 空调运行已确认但设定温度待核对，或车窗留缝已确认但精确开度未知；写清已确认的部分 |
| 待核对 | 没有操作后的有效上报、结果未知，或现场已成功但应用回读仍缺失/不一致 |
| 未开放 | 当前账号或车辆明确未开放该能力，未发送指令 |
| 能力未确认 | 能力或必要车况缺失，刷新后仍无法判断，未发送指令 |
| 失败 | 服务明确拒绝，或已有足够证据确认执行结果与预期不符；保留原始提示和现场事实 |
| 未测 | 环境、车辆条件或本次安排不允许测试；写明原因 |

如果车上已经生效，但 Norr 仍显示旧状态，请写成“现场已生效，页面未更新”，不要只写“成功”或“失败”。这类结果有助于区分控制问题与回读问题。

需要把现场观察写进日志时，在记录仍进行期间打开 **P4 诊断日志 → 添加实车观察（可选）**：

1. **操作位置** 选择证据来源：现场或车机结果选 **车机或车辆**，从官方 App 看到的结果选 **官方 App**。
2. **测试项目** 选择本次实际操作的功能。此下拉框也包含预约等其他项目，不能据此判断 Norr 已实现对应控制。
3. **观察结果** 选择 **观察到预期变化、操作报错、未看到入口、结果未明** 等实际情况。
4. 点 **记录实测结果**，应显示“实测结果已保存在本机”。它会随本轮日志一起导出。

“官方 App 提示已受理”只用于确实在官方 App 看到的提示，不能用来代替 Norr 的服务回执。该表单没有自由备注框，具体档位、时间与现象另记在第 8 节模板中。

## 6. 异常时怎么处理

| 页面现象 | 下一步 |
| --- | --- |
| 车辆未开放此功能 | 记为未开放，保留截图和日志；不强行执行 |
| 能力或对应车况未确认，请刷新车辆 | 回到日志入口刷新车辆、读取车况；仍未确认就保留原因并跳过 |
| 等待操作后的车辆上报 / 未取得对应功能的车辆状态，等待核对 | 补读一次车况，比较车辆上报时间；仍无新证据就记为待核对 |
| 当前回读与目标不一致 | 现场核对，并记录实际状态；可能需要后续新上报才能确定，不立即重发 |
| 超时、网络报错、结果未知 | 先核对车况和现场结果。超时也可能已经送达车辆，不能当作没有执行 |
| 提示先关闭加热或通风，或需要新车况 | 关闭当前模式并等回读；状态未知时先读取，仍不明确则停止切换 |
| 401、登录失效或无权限 | 记下时间和提示，结束并导出当前记录；通过应用正常登录入口恢复后另起一轮 |
| 导出提示请先完成当前文件操作 | 先退出已有文件选择器，再返回日志页面重试导出，无需重做车控 |
| 完成记录前提示读取车况失败 | 查看是否已显示“记录已完成，可导出日志”；若已完成就直接导出已有日志，并注明最后一次读取失败 |

结果不明时，Norr 会先核对同一车辆、同一控制对象的状态，核对期内可能返回原记录或阻止改值。**不要把重复点击当作重试，也不要把等待一段时间当作已确认执行。** 鸣笛与闪灯也有短时间重复发送限制。

## 7. 恢复车辆，结束并导出日志

1. 在结果明确、可以继续操作的前提下，恢复原来的空调、座椅、方向盘、净化及充电上限设置，确认门窗、尾门、口盖和门锁处于需要的状态。恢复操作也留在本轮日志中。
2. 回到 **设置 → 隐私与数据 → P4 诊断日志**，必要时补一次 **读取车况**。
3. 点 **完成记录**。应用会再读一次车况，随后应显示“记录已完成，可导出日志”。
4. 点 **导出日志**，在 iOS 文件选择器中选保存位置，完成保存。回到应用应显示 **日志已导出**。
5. 在“文件”App 中确认 JSON 文件已存在且不是空文件。默认文件名为 `norr-history.json`，建议每轮保存后改成 `P4_B6_日期_时间_测试组.json`，避免覆盖上一轮。
6. 多轮记录时，通过 **已完成的记录** 按开始时间选择，再分别导出。如果新一轮仍在记录，**导出已完成的日志** 导出的是已完成的旧记录；要取得当前轮，需先完成当前记录。

取消文件选择器后可能显示“已取消分享，日志仍保存在本机”。重新点导出即可，取消不会删除记录。不要把普通备份导出当作本轮 P4 诊断日志。

首次使用时，再核对以下日志行为：

| 检查 | 操作与预期 |
| --- | --- |
| 跨页面继续记录 | 开始记录后去控制页操作，再回到设置；仍显示记录中，按钮为完成记录 |
| 手动补读 | 记录中点读取车况，返回结果或明确错误，应用仍能继续操作 |
| 取消导出后重试 | 取消一次文件选择器，再导出；记录仍存在，能够重新保存 |
| 多轮分别导出 | 完成两轮后，按开始时间分别选择和保存；两份日志对应不同记录 |
| 结束后的边界 | 完成一轮后，再开始下一轮才继续车控；新操作不应混入已完成的旧记录 |

日志包含本轮采集的指令提交、服务结果、车辆能力、规范化车况和回读时间。车辆用本轮匿名标识关联；导出会排除密钥、令牌、账号、完整车架号、位置、原始账号响应和签名请求头。它是应用诊断日志，不是原始网络抓包。反馈时仍需自行遮盖截图中的账号、位置和完整车架号。

## 8. 反馈模板

每个异常单独复制一份。正常项目可以只列编号和结论；座椅各档、开启和关闭的结果不同，要分开写。

```text
应用：Norr P4 0.1.0 (6)
iPhone 型号 / iOS 版本：
车辆年款 / 车机版本：
账号类型：主账号 / 共享账号
车辆末四位（可选）：
测试日期、时间及所在时区：
测试编号与动作：例如 C03 方向盘加热，开启
操作前状态 / 车辆上报时间：
操作目标 / 确认执行时间：
Norr 服务回执原文：
Norr 回读原文 / 车辆上报时间：
现场或车机实际结果 / 观察时间：
是否有人同时用官方 App、车机或钥匙操作：
结论：通过 / 部分确认 / 待核对 / 未开放 / 能力未确认 / 失败 / 未测
已恢复的状态或尚待处理事项：
日志文件名：
截图及补充说明：
```
